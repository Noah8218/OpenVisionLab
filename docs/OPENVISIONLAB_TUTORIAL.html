OpenVisionLab Tutorial

OpenCVSharp 기반 Rule-based Vision Workbench를 처음 사용하는 사용자를 위한 이미지 중심 튜토리얼입니다. 목표는 이미지를 불러오고, Tool을 조정하고, Pipeline Recipe를 만들고, 결과를 검증한 뒤 XML로 재사용하는 흐름을 이해하는 것입니다.

1. 기본 개념 빠른 시작 2. Main Workspace 3. 레이어 비교 4. Threshold Tool 5. Pipeline 작성 6. Sample Catalog 7. 검사 폼 티칭 8. AI Recipe 9. 결과 확인 순서
복사/배포용 안내
이 문서는 유지보수용 원본입니다. HTML 파일 하나만 다른 PC나 폴더로 복사해야 하면 이미지가 내장된 OPENVISIONLAB_TUTORIAL_PORTABLE.html을 사용하십시오.

1. 기본 개념

OpenVisionLab은 단순히 이미지를 띄우는 프로그램이 아니라, 검사 조건을 만들고 검증하고 재사용하는 플랫폼입니다.

Layer원본 이미지 또는 처리 결과 이미지를 담는 작업 단위입니다. Main, Threshold, Contour_Result 같은 이름으로 관리됩니다.
ToolThreshold, Morphology, Contour, Blob, Line, Matching 같은 단일 OpenCV 처리 또는 검사 기능입니다.
Pipeline여러 Tool Step을 순서대로 연결한 검사 Recipe입니다. XML로 저장하고 외부 Runner에서도 실행할 수 있습니다.
사용자는 항상 어떤 이미지를 읽는지(Input), 어떤 레이어에 쓰는지(Output), Preview인지 Publish인지, 왜 OK/NG인지를 확인해야 합니다.

처음 보는 순서

처음 사용하는 사용자는 모든 기능을 한 번에 보지 말고, 이미지 로드부터 Sample Catalog 검증까지 한 줄의 흐름으로 보는 것이 좋습니다.

1. Main Workspace이미지를 불러오고 현재 Layer, 결과, 로그 위치를 확인합니다.
2. Tool FormInput Source와 Output Result를 나누어 Threshold, Contour, Blob, Matching 조건을 티칭합니다.
3. Pipeline티칭한 조건을 Step으로 연결하고 Input/Output pill이 의도대로 이어지는지 확인합니다.
4. Sample Catalog샘플 이미지, 추천 Pipeline, 기대 Metric을 함께 열어 기준 결과를 재현합니다.
5. AI RecipeLLM이 만든 XML을 Import하고 Preview 결과와 실패 Step을 기준으로 수정합니다.
핵심 규칙: Main은 기준 원본으로 유지하고, Tool 결과는 별도 Output Layer에 만듭니다. Preview는 확인이고 Publish는 Main Workspace 반영입니다.

2. Main Workspace

Main 화면은 현재 이미지, 레이어, 검사 Step 상태, 로그를 한눈에 보는 작업 공간입니다.

  1. Main 레이어에 기준 이미지를 불러옵니다.
  2. 오른쪽 레이어 / 결과에서 이미지 크기와 현재 표시 레이어를 확인합니다.
  3. 하단 로그에서 이미지 로드, Pipeline 실행, 결과 Publish 로그를 확인합니다.
  4. 결과 레이어가 필요하면 새 레이어를 만들거나 Tool/Pipeline Output으로 생성합니다.
정상 상태: Main 레이어는 기준 이미지로 유지되고, Tool이나 Pipeline 결과는 별도 Output Layer에 표시됩니다.

3. 여러 레이어로 이미지 비교하기

OpenVisionLab은 하나의 이미지만 보는 프로그램이 아닙니다. 원본, 전처리 결과, 최종 검출 결과를 각각 다른 레이어로 남겨 비교하는 것이 핵심 사용 방식입니다.

원본 유지Main 레이어는 기준 이미지로 유지합니다. Tool 결과가 Main을 덮어쓰면 비교 기준이 사라집니다.
전처리 분리Threshold, Morphology, Edge 결과를 별도 레이어에 저장해 검출 전 상태를 확인합니다.
검출 결과 확인Contour, Blob, LineGauge, Matching 결과는 Overlay와 Metric이 남는 최종 레이어로 분리합니다.

권장 비교 흐름

  1. Main에 원본 이미지를 불러옵니다.
  2. Threshold 결과를 Text_Binary, Pin_Binary처럼 별도 Output Layer에 만듭니다.
  3. Morphology 결과를 Text_Clean, Pin_Clean처럼 다음 레이어에 만듭니다.
  4. 최종 검출은 Text_Contour, Pin_Line, Part_Blob, Mark_Match처럼 목적이 드러나는 이름으로 만듭니다.
  5. 오른쪽 레이어 / 결과 목록에서 각 레이어를 선택해 원본, 전처리, 최종 검출 결과를 비교합니다.
확인할 질문정상 기준
Main이 덮어써졌는가?원본은 Main에 그대로 남고, 결과는 별도 레이어에 표시됩니다.
Threshold가 대상을 분리했는가?검출 대상과 배경이 명확히 분리됩니다.
Morphology가 대상을 망가뜨렸는가?노이즈는 줄고, 필요한 대상은 사라지거나 붙지 않습니다.
최종 결과가 확인 가능한가?Box, Line, Label, Score, Metric이 실제 대상 위에 표시됩니다.
Step 흐름이 이해되는가?Pipeline에서 각 Step의 Input/Output pill이 의도대로 연결됩니다.
레이어 비교는 디버깅 도구이기도 합니다. 검출이 안 되면 최종 Tool만 보지 말고, 바로 이전 전처리 레이어부터 확인해야 원인을 빠르게 찾을 수 있습니다.

4. Threshold Tool

Threshold는 가장 기본적인 전처리입니다. 이미지에서 밝기 기준으로 필요한 영역을 분리합니다.

모드언제 사용하는가확인할 것
Basic하나의 기준값으로 밝고 어두운 영역을 나눌 때Threshold 값, Result type
Range특정 밝기 범위만 남길 때Min, Max, Invert
Adaptive조명이 균일하지 않은 이미지에서 지역 밝기 기준으로 나눌 때Method, Block size, Weight
Tool Form에서 Preview는 지정한 Output Layer에 반영되어야 합니다. Main 원본이 의도 없이 덮어써지면 안 됩니다.

5. Pipeline 작성

Pipeline은 반복 가능한 검사 Recipe입니다. Step마다 Input과 Output이 명확해야 합니다.

권장 기본 흐름

Main -> Threshold -> Morphology -> Contour / Blob / Line / Matching -> Metrics + Overlays -> Run Preview -> Publish Result

정상 체인과 Branch

보통 Step은 이전 Step의 Output을 Input으로 읽습니다. 중간에 다시 Main을 읽으면 Branch입니다.

Branch가 항상 잘못된 것은 아닙니다. 다만 사용자가 “왜 이 Step이 이전 Output이 아니라 Main을 읽는지”를 이해해야 합니다.

Input / Output Flow Checklist

LabelMeaningUser check
SOURCEThe first step reads the original image.Usually reads Main.
PREV OUTThe step reads the previous step output.Normal chained inspection flow.
BRANCH INThe step reads another layer instead of the previous output.Keep it only when the branch is intentional.
If a later step reads Main after Threshold/Morphology preprocessing, check the Step I/O panel. Use Link Prev when the step should inspect the processed image.

6. Sample Catalog

Sample Catalog는 학습과 검증의 기준입니다. 샘플 이미지, 추천 Pipeline, 기대 Metric이 함께 제공됩니다.

  1. Pipeline Form에서 Samples를 엽니다.
  2. Recipe Catalog에서 샘플을 선택합니다.
  3. Check Sample로 기준 Metric이 통과하는지 확인합니다.
  4. Open + Preview로 실제 Pipeline 화면에서 결과를 확인합니다.
현재 샘플 카탈로그는 37개 실행 행이 있으며, Required/Explore 샘플 모두 OK 상태로 검증됩니다.

Good / Bad Sample Pair Check

  1. Open the Good sample and run Check Sample. It should pass with a stable metric margin.
  2. Open the Bad sample that uses the same recipe. It should fail for a clear metric, not for a runtime error.
  3. Compare the final layer, overlay count, and key metric such as BoundsWidthMax, ResultCount, ScoreMax, or LineLengthMmMax.
  4. Use the same metric rule as the acceptance condition before saving the recipe.

7. 검사 폼 기반 Tool 티칭 가이드

각 검사 폼은 파라미터를 찾는 공간입니다. 처음부터 Pipeline XML만 수정하는 것보다, 검사 폼에서 실제 이미지와 레이어를 보면서 티칭한 뒤 Pipeline Step으로 넘기는 흐름이 사용자에게 더 직관적입니다.

검사 폼 공통 티칭 순서

  1. Main Workspace에서 원본 이미지를 Main 레이어에 불러옵니다.
  2. 검사 폼을 엽니다. 예: Threshold, Contour, Blob, Matching, EdgeDetection, LineGauge.
  3. Input Layer를 선택합니다. 첫 전처리는 보통 Main, 두 번째 이후 검사는 이전 Output Layer를 선택합니다.
  4. Output Layer를 지정합니다. 원본과 비교할 수 있도록 Input과 다른 이름을 사용합니다.
  5. ROI가 필요하면 먼저 ROI를 잡습니다.
  6. TrackBar, ComboBox, Numeric 설정을 바꾸며 Preview를 확인합니다.
  7. 검출 Overlay와 Metric이 기대 수준이면 Pipeline Step으로 추가합니다.
  8. Main Workspace 또는 Pipeline Preview에서 Input/Output 레이어를 다시 비교합니다.

검출 성공 판단 기준

항목확인 기준
Result image결과 이미지에 대상 위치가 명확히 표시됩니다.
OverlayBox, Line, Cross, Label이 실제 대상 위에 올라갑니다.
MetricResultCount, Area, Score, LineLength, Angle, BoundsWidth가 기대 범위에 있습니다.
LogErrorCode가 없고 ResultStatus가 OK/Passed 흐름으로 남습니다.
Pipeline 재현같은 설정을 Pipeline Run Preview에서도 실행했을 때 같은 결과가 나옵니다.
Contour, Blob, LineGauge 같은 검사 폼 내부에도 Threshold 옵션이 있을 수 있습니다. 별도 Threshold/Morphology Step을 이미 사용 중이라면, 검사 Tool 내부 Threshold가 중복으로 켜져 있는지 반드시 확인해야 합니다.

아래 항목은 Tool별로 처음 테스트할 때 확인해야 하는 기준입니다.

Tool추천 샘플기본 테스트 흐름확인할 Metric / Overlay
Contour Contour_TextSymbols, DiePad_Surface Main -> Threshold -> Morphology -> Contour ResultCount, AreaMin/Max/Avg, Object Box Overlay
Blob Rice_Particle_Blob Main -> Threshold -> Morphology -> Blob ResultCount, BoundsWidthAvg, AreaAvg
Pattern Matching Contour_TemplateMatching Main -> Matching 또는 ROI 지정 후 Matching ScoreMax, ResultCount, Match Box Overlay
FeatureMatching Feature_TemplateReview Main -> FeatureMatching ScoreMax, ResultCount, Homography Box Overlay, Detected Crop
EdgeDetection Pins_LineGauge, SurfaceDefect_Edge Main -> Filter -> EdgeDetection Edge 이미지가 끊기지 않는지, 배경 노이즈가 과도하지 않은지 확인
LineGauge Pins_LineGauge Main -> Filter -> EdgeDetection -> LineGauge EdgeCount, LineLengthMax, LineLengthMmMax, LineAngleAvg, Fit Line Overlay
거리 / 치수 측정 BentPin_GoodShaft, BentPin_BadShaft, Pins_LineGauge Contour/Blob/LineGauge 결과에서 폭, 길이, 각도, Edge 간격을 Metric으로 비교 BoundsWidthMax, BoundsWidthMmMax, BoundsHeightMmMax, LineLengthMmMax, LineAngleAvg, PIXELPERMM

검사 폼과 검출 결과 예시

검사 폼은 파라미터를 찾는 곳이고, Sample/Pipeline Preview는 그 파라미터가 실제 검출로 이어지는지 확인하는 곳입니다. 아래 검사 폼 이미지는 좌측 Input/Output 이미지와 우측 Property를 함께 보여주는 전체 Form 기준입니다.

Contour

Input/Output Layer를 정한 뒤 Threshold, ROI, Area 범위를 조정합니다. 최종 결과에서는 도형, 글자, 숫자 단위로 Box가 대상 위에 올라와야 합니다.

Blob

Blob은 분리된 객체 수와 크기를 안정적으로 세는 용도입니다. Threshold/Morphology 결과가 붙거나 끊기면 Count와 Area 기준이 흔들립니다.

Pattern Matching

Matching은 기준 패턴, 검출된 crop, Overlay 위치를 함께 봐야 합니다. 기준 패턴은 찾으려는 형상만 타이트하게 crop해야 하며, 넓은 배경이나 주변 버튼이 포함되면 사용자가 오검출로 판단하기 쉽습니다.

FeatureMatching

FeatureMatching은 단순 밝기 패턴보다 회전, 스케일, 원근 변화에 더 강한 특징점 기반 매칭입니다. Pattern Matching과 마찬가지로 Template, Detected Crop, Overlay 위치, Score를 함께 확인해야 합니다.

  1. Pipeline Form에서 Samples를 엽니다.
  2. Feature_TemplateReview를 선택합니다.
  3. Open + Preview 또는 Run Preview를 실행합니다.
  4. Feature_Result 레이어, Template, Detected Crop, Score, Overlay를 함께 확인합니다.

EdgeDetection

EdgeDetection은 후속 LineGauge나 치수 측정의 입력이 되는 전처리 결과입니다. 끊긴 Edge와 배경 노이즈가 너무 많으면 다음 Step에서 NG가 납니다.

LineGauge / 치수 측정

LineGauge는 Edge 후보를 기반으로 직선, 길이, 각도를 계산합니다. Pixel/mm 보정이 맞아야 mm 단위 Metric도 의미가 있습니다.

수직선 라인을 이용한 거리측정 흐름

거리측정은 단순히 Edge 이미지를 보는 것으로 끝나지 않습니다. 측정 ROI 안에 여러 개의 수직 스캔 라인을 배치하고, 각 라인에서 Edge 후보를 찾은 뒤 Pixel/mm 보정값으로 실제 치수 Metric을 계산해야 합니다.

  1. Pixel/mm 값을 먼저 확인합니다. 보정값이 틀리면 mm 단위 결과도 모두 틀어집니다.
  2. 측정할 영역을 가로지르는 ROI를 지정합니다.
  3. EdgeDetection 또는 Tool 내부 Threshold로 측정 대상의 경계를 분리합니다.
  4. ROI 안에 여러 수직 스캔 라인을 만들고, 각 라인에서 위/아래 또는 좌/우 Edge 후보를 찾습니다.
  5. 노이즈 후보를 제외하고 유효 Edge 포인트만 남긴 뒤 평균 거리, 최대 거리, 최소 거리, 각도 Metric을 계산합니다.
  6. LineLengthMmMax, BoundsWidthMmMax, BoundsHeightMmMax, LineAngleAvg 같은 Metric으로 OK/NG 기준을 만듭니다.

Contour 테스트 순서

  1. Threshold로 대상이 흰색 또는 검정색으로 분리되는지 확인합니다.
  2. Morphology로 작은 노이즈를 줄이되 대상이 붙어버리지 않는지 확인합니다.
  3. Contour의 Min/Max Area를 조정해 필요한 도형, 글자, 숫자만 남깁니다.
  4. Overlay Box가 ROI 전체가 아니라 실제 object 단위로 그려지는지 확인합니다.

Blob 테스트 순서

  1. 연결된 객체를 세야 하는 이미지에서 사용합니다.
  2. Threshold/Morphology 결과가 객체별로 분리되어 있는지 먼저 확인합니다.
  3. ResultCount와 평균 폭/면적 Metric이 기대 범위에 들어오는지 확인합니다.

Pattern Matching 테스트 순서

  1. 찾을 기준 패턴 이미지는 대상 형상만 타이트하게 잘라 등록합니다.
  2. ROI를 좁혀 오검출 가능성을 줄입니다.
  3. ScoreMax가 충분히 높은지 확인하고, 여러 후보가 나오면 Score와 위치를 함께 봅니다.

Edge / Line / 거리 측정 테스트 순서

  1. Filter로 노이즈를 줄인 뒤 EdgeDetection을 적용합니다.
  2. LineGauge는 Edge 이미지 또는 원본 이미지에서 scan 방향, polarity, ROI를 조정합니다.
  3. 거리/치수 측정은 Pixel/mm 보정값을 먼저 확인한 뒤 BoundsWidthMmMax, BoundsHeightMmMax, LineLengthMmMax, 각도 Metric으로 OK/NG 기준을 만듭니다.
처음에는 Tool Form에서 단독으로 파라미터를 찾고, 값이 안정되면 Pipeline에 Step으로 추가하십시오. 최종 판단은 항상 Preview Image, Overlay, Metric, Log를 함께 보고 결정해야 합니다.

8. AI Recipe

AI Recipe는 최종 결정자가 아니라 Recipe Assistant입니다. LLM이 XML을 제안하면 OpenVisionLab이 실제 이미지로 검증합니다.

사용자 이미지 + 검사 목표 -> LLM이 Pipeline XML 제안 -> OpenVisionLab에서 Import -> XML Validation -> Run Preview -> 실패 Step 확인 -> 파라미터 또는 Layer Flow 수정 -> 다시 Preview -> Save / Publish
AI가 만든 Recipe라도 최종 검증은 실제 이미지, Overlay, Metrics, OK/NG 기준으로 해야 합니다.

9. 결과 확인 순서

결과가 이상할 때는 아래 순서로 확인합니다.

  1. Step Flow에서 Input Layer가 맞는지 확인합니다.
  2. Output Layer가 비어 있거나 이전 결과를 덮어쓰는지 확인합니다.
  3. Run Preview가 실행되었는지 확인합니다.
  4. Result Grid의 Status와 Message를 확인합니다.
  5. Run Log의 첫 번째 NG Step을 확인합니다.
  6. DiagnosticHint와 SuggestedFix를 확인합니다.
  7. Sample Catalog의 비슷한 Recipe를 참고합니다.
