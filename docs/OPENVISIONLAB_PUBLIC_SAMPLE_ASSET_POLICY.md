# OpenVisionLab Public Sample Asset Policy

Updated: 2026-07-03

OpenVisionLab will be opened on GitHub, so sample images must be treated as redistributable project assets, not as local SDK examples.

## Rule

Do not commit, document, or publish sample images copied from commercial SDK installations unless the vendor license explicitly allows redistribution in a public repository.

This applies to:

- Original sample images
- Cropped templates
- Result images generated from those samples
- Tutorial screenshots where those images are visible
- Annotated/callout images derived from those screenshots

## Current Local Risk

Developer machines may have a root `Sample` directory with local SDK/vendor examples used for private comparison or migration checks. That directory is ignored and must stay outside the public Git tree unless every asset has a verified redistribution license.

Do not use the root `Sample` directory as the source for:

- README images
- Public project brief images
- Public tutorial captures
- Required CI/smoke test assets
- New sample catalog rows intended for GitHub distribution

## Allowed Sources

Use these sources first:

1. **Project-authored synthetic images**
   - Generated by OpenVisionLab scripts.
   - Stored under `docs/samples/public`.
   - Best default for rule-based tool demos because ground truth is known.

2. **Self-created real captures**
   - Captured by the project owner.
   - No third-party logo, UI, dataset, or device documentation visible unless cleared.
   - Store a short provenance note.

3. **External datasets with explicit redistribution license**
   - Keep only datasets whose license permits public redistribution.
   - Record dataset name, URL, license, file names, and any attribution requirement.
   - Prefer permissive licenses for default repo assets.

## External Dataset Notes

- MVTec AD (`https://www.mvtec.com/research-teaching/datasets/mvtec-ad`) is useful for industrial anomaly detection research, but it is released under CC BY-NC-SA 4.0. Do not use it as a default OpenVisionLab public sample set because the non-commercial/share-alike terms are not aligned with a broadly reusable GitHub project.
- Open Images (`https://github.com/openimages/dataset`) uses Creative Commons licensed images, but the project notes that each image license should still be verified. Use it only through a manifest with per-image attribution and license checks.
- DeepPCB (`https://github.com/tangsanli5201/DeepPCB`) is a better candidate for PCB-style samples because its repository advertises an MIT license. Still record the exact files used and attribution before adding assets.

## Required Manifest

Every public sample asset must have a manifest row:

```csv
AssetPath,SourceType,SourceName,SourceUrl,License,Attribution,GeneratedBy,Notes
docs/samples/public/Matching_DiePad_Synthetic_OK.png,Synthetic,OpenVisionLab,,,,tools/GenerateOpenVisionSyntheticSamples.ps1,Generated grayscale matching sample
```

## Capture Rule

Documentation capture must use only public-safe sample sources. If a screenshot includes a local SDK sample image, do not commit it to README, tutorial, Learn, project brief, or public release assets.

Public-facing text must describe the product and its verified behavior. Do not add personal submission purpose, private notes, or maintainer-only context to README, tutorial, Learn, sample policy, or project brief documents.

Before publishing:

1. Run sample-source audit.
2. Regenerate tutorial captures from public-safe samples.
3. Check that `docs/assets/tutorial/current` and `docs/assets/tutorial/annotated` do not visibly contain SDK sample images.
4. Keep any local SDK sample tests opt-in and skipped by default.

Required checks:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\GenerateOpenVisionSyntheticSamples.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File tools\GenerateOpenVisionProductSamples.ps1
```
