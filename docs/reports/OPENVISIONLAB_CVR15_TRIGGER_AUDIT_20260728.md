# OpenVisionLab CVR-15 Activation Audit

Date: 2026-07-28  
Queue item: `CVR-15` — synthetic edge-model / geometry teaching  
Decision: **Not admitted — real no-template geometry packet absent**

## 1. Question Audited

Should OpenVisionLab add a way to author an EdgeBasedMatching model from
operator-specified geometry when no usable Good template image exists?

The VisionPro PMAlign commercial reference shows that a pattern can be taught
from synthetic shape when a representative Good image is unavailable. That is
a useful commercial lesson, but it is not enough to choose a product contract.
The project first needs a real part whose certified geometry is known and whose
current image-template path demonstrably cannot express the task.

## 2. Existing Responsibilities

| Existing path | Current behavior | Why it is not CVR-15 completion |
| --- | --- | --- |
| Matching / EdgeBasedMatching template teaching | Registers a reviewed ROI from an input image and persists a raster `PATTERN_PATH` | Requires a usable image template; it does not author geometry |
| Auto MPoint | Ranks image windows and replays them on representative images before explicit operator apply | Suggests raster image regions; it cannot invent or certify a physical model |
| EdgeDetection / Threshold / Contour | Produces current-image pixels, masks, or object evidence | Runtime segmentation is not a reusable pose-search model |
| Line, CircleGauge, GeometryMeasure | Detects typed Point/Segment/Circle evidence and measures known geometric relations | Measurement features are produced from each runtime image; they are not a synthetic matcher template |
| LineFixture / AffineTransform | Publishes a frame from detected lines or three earlier Points | Consumes detected evidence; it does not define the target from nominal geometry |
| Overlay and review drawings | Displays retained result evidence | Display primitives do not participate in matcher scoring |

Current matcher diagnostics, global polarity, unique-result handling, scalar
angle/scale search, and CVR-10 fan-out operate after a raster template already
exists. None removes the template prerequisite.

## 3. Evidence Inventory Result

The repository contains:

- commercial narration that synthetic PMAlign shapes are possible;
- public and synthetic raster templates for Matching and EdgeBasedMatching;
- operator-reviewed ROI template teaching and Auto MPoint candidate evidence;
- pixel geometry tools for Line, Circle, intersection, distance, and fixture
  construction;
- current-result drawings and deterministic N-image verification.

It does not contain one named packet with:

- a real target for which no usable Good template can be captured or supplied;
- an operator-certified nominal geometry, coordinate system, and tolerance;
- a reviewed mapping from that geometry to the physical image edges that should
  participate in scoring;
- a frozen failure of the current raster-template, LineFixture, or Affine paths;
- representative wrong-target and no-target captures;
- separate Train, Validation, and untouched Held-out replay rows.

Existing SVG, UI drawing, sample-generation, or synthetic-test code is not
physical model evidence. A convenient geometry generated by the project would
only prove that the project can match its own drawing.

## 4. CVR-15 Admission Packet

Reopen CVR-15 only when one packet contains all six sections below.

### A. Named No-Template Task

- part/product and inspection name;
- exact physical feature to locate;
- downstream ROI or measurement that consumes the pose;
- why a representative Good raster template cannot be captured, retained, or
  rendered by an approved upstream source;
- why current LineFixture, three-Point Affine, or a fixed ROI cannot express the
  task.

### B. Certified Geometry And Coordinate Contract

- drawing/CAD/specification revision and source owner;
- certified dimensions and tolerances for every admitted primitive;
- model origin, X/Y axes, handedness, units, and reference pose;
- exact supported primitive subset, such as line segments and circular arcs;
- explicit treatment of gaps, intersections, duplicated edges, and zero-length
  or degenerate primitives.

Screenshots traced by the model or geometry inferred from the same replay
images are not independent certification.

### C. Image-Edge Mapping Contract

Before implementation, the operator must identify:

- which physical boundaries are expected to produce image gradients;
- expected Same/Reversed or global-reversal polarity;
- permitted missing or occluded model portions;
- sampling density, rasterization scale, line width, and antialiasing policy;
- whether the output is a generated raster template for the existing matcher
  or a new bounded model representation.

The first slice must choose one representation. It must not introduce a general
CAD/ODB importer or a free-form vector editor.

### D. Frozen Current-Path Comparison

Replay the applicable current paths with unchanged settings and retain:

- raster template teaching when any approved reference rendering exists;
- LineFixture or Affine when certified datums are detectable;
- exact failure reason, score/pose, runtime, and drawings;
- evidence that the failure is caused by the absence of a usable template,
  rather than ROI, contrast, polarity, angle/scale range, ambiguity, blur,
  occlusion, or an incorrect physical feature.

At least one reproducible operator-blocking failure must remain.

### E. Nuisance And Safety Matrix

Freeze rows covering:

- nominal pose and the approved angle/scale envelope;
- contrast and permitted global-polarity states;
- missing, weak, or partially occluded model edges;
- clutter and repeated wrong geometry;
- dimensionally similar wrong parts;
- crop/border conditions and no-target images;
- deterministic runtime and candidate-budget limits.

The packet must state which missing edges may be tolerated and which must fail
closed. Automatic geometry simplification or gate selection is not admitted.

### F. Split And Completion Gate

- separate Train, Validation, and untouched Held-out rows before implementation;
- source image, geometry revision, configuration, and generated-model SHA-256;
- operator-reviewed pose truth with finite pixel or physical tolerance;
- zero wrong-part and no-target accepts at the frozen task gate;
- retained model preview, selected/alternative result drawings, exact reasons,
  and runtime;
- PropertyGrid/XML/save/reload/report round trip;
- missing XML keys preserve current raster-template behavior;
- geometry edits never trigger Preview/Run or mutate layers/routing.

## 5. First Admitted Implementation Boundary

If the packet passes, the first implementation is limited to:

- one named physical task;
- one certified coordinate contract and one small primitive subset;
- one explicit operator action that creates a versioned, hashable teaching
  artifact;
- reuse of the current EdgeBasedMatching search/ambiguity/report path where the
  admitted representation permits it;
- exact generated-model preview, provenance, validation, and fail-closed
  errors;
- one frozen Train/Validation/Held-out matrix.

It does not authorize general CAD/DXF/ODB import, a vector-CAD editor,
constraint solving, automatic model invention from images, learned shape
matching, deformation, non-uniform scale, perspective calibration, or
commercial-parity claims.

## 6. Decision

CVR-15 is not admitted. No runtime, Library-Noah DLL, PropertyGrid, XML tool
family, sample, or UI change is justified by the current evidence. The
commercial capability remains a conditional product lesson, not an active
feature requirement.
